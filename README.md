# GitHub Issue Triage Agent Suite

This suite provides a production-grade, AI-powered pipeline for triaging GitHub issues. It uses a multi-phase RAG (Retrieval-Augmented Generation) process to ground triage decisions in actual repository documentation and source code.

## System Components

1. **main.py**: The primary triage engine. It fetches issues, indexes the repository via Remote AST parsing of the source code, performs RAG searches on the codebase. It generates two structured triage reports one in human readable markdown and the other a machine readable JSON.

2. **query_reports.py**: A local NoSQL query engine. It allows you to filter and generate specialized sub-reports (e.g., High Priority only) from the JSON data generated by the main engine without incurring additional API costs.

## 1. Setup and Installation

### Prerequisites

* Python 3.11 explicitly installed on your system (or 3.11 conda environment).
* A GitHub Personal Access Token (Classic or Fine-grained)
* An Anthropic, OpenAI, or Gemini API Key

### Installation

1. Clone the repository to your local machine.

2. Create and activate a Python 3.11 virtual environment:
   ```
   python3.11 -m venv triage-agent
   source triage-agent/bin/activate  # On Windows CMD: triage-agent\Scripts\activate
   ```

   or in conda:
   
   ```
   conda create --name triage-agent python=3.11
   conda activate triage-agent
   ```

3. Install the required dependencies from the requirements file:
   
   ```
   pip install -r requirements.txt
   ```

## 2. Environment Configuration

Create a `.env` file in the root directory (see `.env.template`). The application includes an aggressive scrubbing routine to handle hidden spaces or quotes in your keys. Note that there is no default repository configured; you must specify the target repository in the `.env` using:

```
TARGET_REPO=owner/repo
```
or specify it at run time.

You will need to specify a github token to avoid API rate limiting.
```
GITHUB_TOKEN=your_github_token_here
```
### LLM Configurations:
```
# Options: claude-3-5-haiku-20241022 (Default), gpt-4o-mini, etc.
MODEL_NAME=claude-3-5-haiku-20241022
```
You will need to provide an LLM API key:

```
# ANTHROPIC_API_KEY=your_key_here
# OPENAI_API_KEY=your_key_here
# GEMINI_API_KEY=your_gemini_api_key_here
```
Provide the key corresponding to your MODEL_NAME and optionally comment out the others.
## 3. Usage: Triage Engine (main.py)

The triage engine fetches open issues and performs a two-pass LLM analysis. Because there is no default repository, either the `TARGET_REPO` (preferred) environment variable or the `--repo` flag is mandatory for every run.

### Command Line Options

| Option | Description | Default | 
| ----- | ----- | ----- | 
| `--repo` | The GitHub repository (owner/repo). | None | 
| `--page_size` | Number of valid issues to process in one batch (Max: 10). | 2 | 
| `--start_issue` | Starting issue number. Skips any issues newer than this. | None | 
| `--max_code_files` | Max remote Python files to index via AST for RAG. | 200 | 
| `--include_labeled` | If true, processes issues that already have labels. | False | 

### Example
Triage unlabeled issues from scanpy fork:
```
python main.py --repo jameswilsenach/scanpy --page_size 3
```

### Outputs

* Logs: Detailed OpenTelemetry traces in `logs/[repo]_[timestamp].txt`.
* Markdown Report: Human-readable summaries in `reports/[repo]_triage_[timestamp].md`.
* JSON Database: Structured NoSQL data in `reports/[repo]_triage_[timestamp].json`.

## 4. Usage: Query Engine (query_reports.py)

Once you have generated a JSON report, use this tool to create specialized sub-reports without further LLM calls.

### Command Line Options

| Option | Description | 
| ----- | ----- | 
| `--input_json` | Path to a specific JSON report. Defaults to the latest. | 
| `--repo` | Help find the latest report for a specific repository. | 
| `--high_priority` | Generate report for 'High' priority issues. | 
| `--low_priority` | Generate report for 'Low' priority issues. | 
| `--high_upstream` | Generate report for 'High' upstream risk issues. | 
| `--needs_info` | Generate report for issues requiring user info. | 

### Example

Filter the latest report for high priority and upstream risks
```
python query_reports.py --repo jameswilsenach/scanpy --high_priority --high_upstream
```

## 5. Technical Design Principles

* Parsimonious RAG: Uses Remote AST parsing to extract function and class definitions directly from GitHub, providing code-level context without requiring a local clone.
* Structured Output: Uses Pydantic and Instructor to guarantee that triage decisions (priority, risk, labels) follow a strict schema.
* Traceability: Every report entry includes the specific RAG chunks (file and line number) used by the LLM to make the decision.
* Bounded Behavior: Implements hard caps on batch sizes and file indexing to limit compute and protect API credit overuse.
